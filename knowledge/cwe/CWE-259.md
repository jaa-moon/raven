# CWE-259: Use of Hard-coded Password

## Description

CWE-259 occurs when software contains a hard-coded password or secret that is used
for its own authentication or for authentication with external components. Hard-coded
credentials are static and cannot be changed without modifying the source code and
redeploying the application.

## Risk

- **CVSS Score**: Up to 9.8 (Critical)
- **Impact**: Unauthorized access to the application, database, or external services
- **OWASP**: A02:2021 — Cryptographic Failures / A07:2021 — Identification and Authentication Failures
- **Affected Languages**: All

## Vulnerable Example (Python)

```python
# VULNERABLE: hardcoded credentials
app.secret_key = "supersecretkey123"
DB_PASSWORD = "admin123"
API_KEY = "sk-abc123def456"

# Anyone with read access to this file has these credentials permanently
```

## Vulnerable Example (JavaScript)

```javascript
// VULNERABLE
const dbConfig = {
  password: "mypassword123",
  apiKey: "Bearer eyJhbGci..."
};
```

## Safe Example (Python)

```python
# SAFE: load from environment variables
import os
from dotenv import load_dotenv

load_dotenv()

app.secret_key = os.environ["SECRET_KEY"]
DB_PASSWORD = os.environ["DB_PASSWORD"]
API_KEY = os.environ["API_KEY"]
```

## Remediation

1. **Remove all hardcoded credentials** from source code immediately.
2. Store secrets in environment variables and load them at runtime.
3. Use a `.env` file (with `python-dotenv`) for local development — add `.env` to `.gitignore`.
4. For production, use a secrets manager: AWS Secrets Manager, HashiCorp Vault, or Azure Key Vault.
5. **Rotate all exposed credentials immediately** if they have been committed to version control.
6. Use git history scanning tools (e.g. `truffleHog`, `gitleaks`) to detect historical exposure.
